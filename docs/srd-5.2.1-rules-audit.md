# SRD 5.2.1 rules-application audit

Spec 02a, workstream C. Every mechanic row of [the capability matrix](capabilities.md) is checked against the text of SRD 5.2.1: the section that governs it, the rule it states, whether the engine applies it that way, and the tests that pin it. Where the engine differs, SRD 5.2.1 is the rule and the difference is recorded in `BACKLOG.md` under "SRD 5.2.1 rules-application audit".

Each row was read against the SRD text and checked by running the engine, not only by reading its code. `packages/dnd5e-engine/tests/test_rules_audit.py` keeps this page honest: every mechanic row of `capabilities.md` has a row here with the same status, every row cites at least one test that exists and whose docstring or comments name one of the row's SRD sections, and every divergence names a `BACKLOG.md` entry that exists. A test that states the SRD's outcome where the engine differs is a strict `xfail`: fixing the engine makes it pass unexpectedly, which fails the suite until the marker is removed.

Verdicts: **Matches** (the engine applies the rule as written, apart from gaps `BACKLOG.md` already records), **Diverges** (the engine applies it differently; the row names the entry), **Not modelled** (the row says so, and the audit confirms it), **Engine design** (no SRD rule governs it).
